## Initial Deployment Attempt and Observed Blocker

The first Vercel import/deployment attempt did not create a deployment record.

Vercel rejected the project configuration before the build/deployment was created because
the Test project was on the Hobby plan while the repository declared cron schedules more
frequent than once per day.

The approved schedules at the time were:

```text
/api/cron/sync-airbnb-calendars
  */30 * * * *

/api/cron/expire-pending-reservation-holds
  */5 * * * *

/api/cron/process-email-notifications
  */5 * * * *

/api/cron/schedule-arrival-instructions
  */30 * * * *
```

Current Vercel provider behavior verified on 2026-08-10:

```text
Hobby minimum cron interval: once per day
Pro minimum cron interval: once per minute
Hobby cron expressions that run more frequently than daily fail during deployment
Cron jobs declared in vercel.json are registered when a Production Deployment is created
```

Official references:

- https://vercel.com/docs/cron-jobs/usage-and-pricing
- https://vercel.com/docs/cron-jobs/quickstart
- https://vercel.com/docs/cron-jobs/manage-cron-jobs

This was a platform-plan/configuration rejection, not evidence of a Next.js compilation,
database, Auth.js, Cloudinary, Tilopay, or application-runtime failure.

## Corrected Phase Boundary

12.2 through 12.6 must not register Vercel cron schedules.

The repository therefore intentionally uses:

```json
{
  "crons": []
}
```

This change affects only Vercel scheduler registration.

It does **not**:

```text
- delete any /api/cron/* route;
- change cron handler behavior;
- change cron authorization;
- change CRON_SECRET requirements;
- change the approved 5/30-minute frequencies;
- replace Vercel Cron with another provider;
- change Reservation, Payment, EmailNotification, Airbnb, or lifecycle behavior.
```

The approved scheduler configuration is deferred intact to 12.7.
