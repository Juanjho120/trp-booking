## Hardening Decision

The hosted edge already provides HSTS with a two-year max-age, so this package does not duplicate or
override `Strict-Transport-Security` at the application layer.

The application adds the following low-risk response protections globally:

```text
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: camera=(), microphone=(), geolocation=(), browsing-topics=()
X-Frame-Options: SAMEORIGIN
```

It also disables the default technology disclosure:

```text
X-Powered-By: removed
```

These controls do not change CORS, cookies, Auth.js session semantics, Tilopay credentials, payment
callbacks, Cloudinary access, Airbnb iCal behavior, Resend delivery, database access, or cron
authorization.

## CSP Decision

A comprehensive `Content-Security-Policy` is intentionally **not** added in this package.

The accepted payment implementation dynamically loads the Tilopay SDK from:

```text
https://app.tilopay.com/sdk/v2/sdk_tpay.min.js
```

A correct CSP must account for the complete runtime origin requirements for script, connection,
frame, image, and style behavior, not just the initial SDK script URL. Freezing an incomplete policy
could make the hosted checkout fail while appearing secure in static review.

Therefore the 12.9 decision is:

```text
CSP outcome: Option B
Comprehensive CSP enforcement remains an explicit Phase 13 go-live gate.
```

Phase 13 must inventory the actual Production provider/runtime origins and validate the final CSP
against:

```text
- public ES/EN navigation
- Cloudinary images
- Google/Auth.js sign-in and callback
- admin UI
- Tilopay Production checkout initialization and completion
- same-origin application APIs
```

This deferral does not weaken the independent low-risk controls implemented by this package.
