## Observed Problems

```text
1. Creating a DATE_CHANGE or STAY_EXTENSION frequently returns HTTP 500 on the first attempt; immediate replay succeeds.
2. The Fechas solicitadas calendar opens below helper/status copy instead of directly below the trigger input.
3. Approving a request frequently returns HTTP 500 on the first attempt; immediate replay succeeds.
```

The create and decision paths both execute long interactive `Serializable` transactions. Before this correction they specified only the isolation level, so connection wait and transaction execution used Prisma's implicit defaults. Both paths also handled a final `P2034` conflict after the transaction failed, but did not retry the complete idempotent transaction first.

The repeated first-failure/second-success pattern is consistent with a cold or contended first interactive transaction exceeding its wait/execution window, or a transient serializable conflict that succeeds after the concurrent work clears. The correction addresses both conditions without weakening isolation.

## Transaction Correction

Both date-mutation interactive transactions now use:

```text
isolationLevel = Serializable
maxWait = 10,000 ms
timeout = 20,000 ms
```

A shared bounded wrapper retries only Prisma `P2034` serialization/write-conflict failures:

```text
Maximum attempts: 3
Delay: 75 ms × completed failed attempt
Retry unit: the complete idempotent transaction
```

The existing post-retry behavior remains unchanged:

```text
- P2002/idempotency recovery still resolves an already-created request.
- Same-decision replay still returns the existing result.
- Opposite decisions still conflict.
- Active-request and stale-state guards remain authoritative.
- No timeout or serialization failure is converted into a successful response without confirmed persisted state.
```

## Datepicker Positioning Correction

The `AvailabilityDateRangePicker` root no longer owns popup positioning. A new trigger-only `relative` wrapper contains the button and absolute calendar popup. Helper and status copy remain below the trigger in normal document flow.

Result:

```text
- Closed state: label, trigger, helper, and status retain the existing order.
- Open state: the calendar starts immediately below the trigger input.
- The popup no longer uses helper/status height when calculating top-full.
- Selection, blocked dates, hover preview, month navigation, clear/done actions, and accessibility behavior remain unchanged.
```
