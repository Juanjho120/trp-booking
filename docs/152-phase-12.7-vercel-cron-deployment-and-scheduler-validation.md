## Current Vercel Platform Contract

Verified against official Vercel Cron Jobs documentation on 2026-08-10:

```text
- Cron Jobs are configured through vercel.json/build output and invoke Vercel Functions.
- Vercel invokes configured crons only on Production Deployments, not Preview Deployments.
- Cron expression timezone is UTC.
- Hobby is limited to once-per-day schedules and hourly precision.
- Pro supports intervals as frequent as once per minute with per-minute precision.
- A project CRON_SECRET is automatically sent by Vercel as Authorization: Bearer <CRON_SECRET>.
- Failed cron invocations are not automatically retried by Vercel.
- Cron invocations can overlap if a prior function is still running; application locking/idempotency remains required.
- Vercel may occasionally deliver the same cron event more than once; jobs must remain idempotent.
- Cron requests do not follow redirects.
- Active jobs are visible under the project's Cron Jobs settings and link to Runtime Logs.
- Instant Rollback does not automatically rewrite active cron registrations; cron state must be reviewed explicitly after a rollback.
```

These platform behaviors reinforce the already-accepted Package C overlap lock and domain idempotency contracts; they do not require a new scheduler architecture.
