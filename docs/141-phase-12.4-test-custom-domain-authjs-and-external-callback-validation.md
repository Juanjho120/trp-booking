## Step 4 — Validate Auth.js Host Inference Before Setting AUTH_URL

Keep:

```text
AUTH_TRUST_HOST=true
```

Do **not** add `AUTH_URL` initially. This is an intentional correction to the earlier Phase 12 planning assumption. The current repository explicitly treats `AUTH_URL` as optional, the `.env.example` states that Auth.js v5 usually infers the host from trusted request headers, and `auth.ts` passes the validated `AUTH_TRUST_HOST` value to `trustHost`.

With the stable Test domain already valid, open:

```text
https://trp-booking.juantzun.dev/api/auth/providers
```

The Google provider must expose/use this callback URL:

```text
https://trp-booking.juantzun.dev/api/auth/callback/google
```

If the generated callback is correct:

```text
AUTH_URL remains absent.
```

If it points to localhost, a `*.vercel.app` alias, the wrong scheme, or another host, **stop 12.4 at that point**. Do not blindly add an `AUTH_URL` value. Capture the provider output/runtime log and correct the observed Auth.js host/base-path behavior deliberately.
