Connect the **real Airbnb export calendars** for the three real listings to the hosted TRP Booking Test environment and validate the already-implemented inbound iCal import path.

12.5 is not a new synchronization implementation. The repository already contains:


## Official Airbnb Provider Procedure — Verified 2026-08-10

```text

-> select the listing calendar

-> Connect to another website
```

Airbnb states that the calendar link used for iCal synchronization should end in `.ics`.

That Airbnb refresh behavior becomes more relevant in 12.6 when TRP's outbound feed is connected back to Airbnb; 12.5 validates the opposite direction.

## Step 2 — Identify the Existing ExternalCalendar IDs

Before building `AIRBNB_ICAL_IMPORT_URLS_JSON`, identify the actual database records.

In the Supabase SQL editor for the shared Local/Test database, run:

```sql
select
    id,
    property_id,
    provider,
    direction,
    name,
    is_import_enabled,
    is_export_enabled,
    status,
    last_import_started_at,
    last_import_finished_at,
    last_failure_code
from trp_booking.external_calendars
where provider = 'AIRBNB'
  and deleted_at is null
order by property_id, id;
```

Expected logical mapping:

```text
one active import-capable calendar -> black-white-apartment
one active import-capable calendar -> perfect-retreat-bungalow
one active import-capable calendar -> complete-retreat
```

Import-capable means:

```text
direction = IMPORT or BIDIRECTIONAL
is_import_enabled = true
status != INACTIVE
```

### If three usable records already exist

Use their **actual `id` values** in Step 3.

### If one or more records are missing

Do not invent environment keys.

Create/repair the `ExternalCalendar` configuration first using the existing schema contract, then continue.

The database model defaults support Airbnb/BIDIRECTIONAL/ACTIVE configuration, but the exact insert/update must be based on the rows that actually exist in the shared database so duplicate calendar records are not created accidentally.

## Step 6 — Verify Persistence Safely

Inspect calendar state without exposing the URLs.

### External calendars

```sql
select
    id,
    property_id,
    name,
    status,
    last_import_started_at,
    last_import_finished_at,
    last_failure_code,
    last_failure_message
from trp_booking.external_calendars
where provider = 'AIRBNB'
  and deleted_at is null

```

Expected:

```text
status = ACTIVE
last_import_started_at populated
last_import_finished_at populated
last_failure_code null
```

### Sync logs

```sql
select
    id,
    external_calendar_id,
    triggered_by,
    status,
    started_at,
    finished_at,
    events_imported,
    events_updated,
    events_removed,
    events_skipped,
    blocks_created,
    blocks_updated,
    error_code
from trp_booking.external_calendar_sync_logs
order by created_at desc
limit 20;
```

Expected manual execution source:

```text
triggered_by = ADMIN
```

and no raw Airbnb URL/token in error fields.

### Imported events

```sql
select
    external_calendar_id,
    provider_event_uid,
    status,
    start_date,
    end_date,
    first_seen_at,
    last_seen_at,
    removed_at
from trp_booking.external_calendar_events
order by last_seen_at desc
limit 50;
```

Do not select or copy unnecessary raw payload data during routine acceptance.

### Airbnb calendar blocks

```sql
select
    id,
    property_id,
    source,
    start_date,
    end_date,
    external_calendar_event_id,
    parent_block_id,
    deleted_at,
    unlocked_by_admin_at
from trp_booking.calendar_blocks
where source in ('AIRBNB', 'PREPARATION_BUFFER')
order by start_date desc
limit 100;
```

## Step 7 — Validate Availability Propagation

For at least one imported Airbnb unavailable range, verify the hosted public/admin calendars.

Expected composed-listing rules:

```text
Airbnb Apartment occupied
-> Apartamento Blanco y Negro blocked
-> Refugio Completo blocked

Airbnb Bungalow occupied
-> Bungalow Refugio Perfecto blocked
-> Refugio Completo blocked

Airbnb Refugio Completo occupied
-> Refugio Completo blocked
-> Apartamento Blanco y Negro blocked
-> Bungalow Refugio Perfecto blocked
```

Preparation buffers must also follow the accepted property settings for real imported Airbnb reservations:

```text
Apartamento Blanco y Negro: 1 day before / 1 day after
Bungalow Refugio Perfecto: 2 days before / 2 days after
Refugio Completo: 2 days before / 2 days after
```

Accepted 12.5.1 correction: only events classified as real provider reservations (`Reserved`) generate these TRP preparation buffers. Generic `Airbnb (Not available)` / unknown active provider unavailability remains blocking for its provider dates but does not receive another TRP preparation buffer.

Admin-unlocked preparation days remain governed by the existing override behavior.
